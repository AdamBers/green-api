# Green Chat

Адаптивный WhatsApp-клиент на React и TypeScript для тестового задания GREEN-API.
Выбран разрешённый в задании вариант WhatsApp, интерфейс ориентирован на WhatsApp Web.

## Запуск

Node.js 22.12+ (ветка 22) или 24+, npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).
На экране подключения нажмите **Открыть демоверсию**. Реальный инстанс не нужен.

## Что работает сейчас

- Адаптивный интерфейс: список и переписка на desktop, отдельные представления на mobile.
- Создание чатов по международному номеру, валидация, предотвращение дублей, поиск.
- Отправка текста, переносы строк, статусы, автоматический явно обозначенный демоответ.
- Активный чат и поиск в URL; браузерные переходы назад/вперёд.
- Сессия, список чатов и сообщения восстанавливаются при обновлении страницы.
- Диалоги с клавиатурной навигацией, Escape и возвратом фокуса.
- Выход очищает локальные данные; поздние результаты отправки не возвращают старую сессию.

Деморежим не отправляет запросы или сообщения в GREEN-API/WhatsApp.
После закрытия вкладки её данные не сохраняются между новыми сессиями.

## Подключение GREEN-API — следующий этап

HTTP-методы, проверка состояния инстанса, загрузка последних 100 текстовых сообщений,
отправка, последовательный long polling и подтверждение уведомлений подготовлены в коде.
По умолчанию реальное подключение **выключено** и не проверено с живым инстансом.

Для следующего этапа потребуется:

1. Зарегистрироваться на https://console.green-api.com/.
2. Создать WhatsApp-инстанс и привязать приложение WhatsApp через QR-код.
3. Оставить Webhook URL пустым; включить входящие сообщения, статусы исходящих сообщений,
   уведомления о сообщениях, отправленных через API и с телефона.
4. Создать `.env.local` с `VITE_ENABLE_LIVE_API=true` и перезапустить Vite.
5. Ввести `apiUrl`, `idInstance`, `apiTokenInstance` из кабинета в форму приложения.
6. Проверить обмен сообщениями с другим WhatsApp-аккаунтом, CORS, реальные форматы ответов,
   восстановление истории и ограничения тарифа.

Не помещайте токен в `.env`, код или Git. Приложение получает его из формы и хранит в
`sessionStorage`. API использует токен в пути запроса, cookie-авторизации для этих методов нет.
На Developer доступны только три чата. Группы, файлы и бесконечная загрузка истории не входят в объём.

## Архитектура

```text
app        — providers, router, глобальные CSS-токены
pages      — композиция экранов
widgets    — список чатов и переписка
features   — подключение, выход, создание чата, отправка и получение
entities   — session, chat, message, notification: модели, API, presentation-only UI
shared     — Axios, ошибки, общие UI-компоненты, технические helpers
```

HTTP-функции: `entities/<domain>/api.ts`.
Прямые query/mutation hooks: только `features/<domain>/hooks`; текущие запросы находятся в
`features/session/hooks` и `features/message/hooks`. В них нет демотаймеров или сценария подключения.
Сценарные hooks: корневая точка feature без UI либо `model` соответствующей feature.
Формы: React Hook Form + Zod. Стили: SCSS Modules. Barrel-файлов нет.

Zustand persist хранит credentials и чаты в `sessionStorage`.
Сторы находятся в `entities/session/store/sessionStore.ts` и `entities/chat/store/chatStore.ts`.
Сообщения находятся только в TanStack Query cache, который также сохраняется в `sessionStorage`.
`useMessagePreviewsQuery` только наблюдает кеш, не загружая историю каждого чата.
Демоданные создаются сценарием подключения; отправка и повтор используют один сценарный hook
`features/message/sendMessage/useSendMessageFeature.ts`. Очистка данных и создание чата находятся
в `model` соответствующих features; страницы подключают корневые widgets.
Пока вкладка закрыта, браузер не получает события. После подключения историю восстанавливает API,
но доступная история зависит от данных, накопленных GREEN-API.

`normalizeApiError` — единый обработчик ошибок Axios/сети/инстанса.
Он возвращает `AppError` с `kind`, `message`, необязательными `status` и `code`.
Сырой ответ сервера не выводится пользователю. Место показа выбирает сценарий.
Отправка автоматически не повторяется; после прерванного запроса результат может быть неоднозначен.
Polling подтверждает уведомление только после обработки и исключает дубли по ID сообщения.

## Проверки

```sh
npm run type-check
npm run lint
npm test
npm run build
npm run test:e2e
```

E2E запускается в установленном Google Chrome, на desktop и mobile viewport.
Unit-тесты проверяют обработку ошибок, слияние сообщений и порядок обработки очереди.
E2E проверяет создание чата, отправку, сохранение, выход и доступность диалогов.

```sh
npm run format
npm run format:check
```

Для публикации используйте статический хостинг с fallback на `index.html` и HTTPS.
Продакшен-сборка находится в `dist`; публикация пока не выполнялась.
